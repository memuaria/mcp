# Как помочь проекту Memuaria MCP

Спасибо за интерес к Memuaria MCP. Этот репозиторий — публичная точка входа для документации, настроек подключения, проверок совместимости и обратной связи по официальному MCP-серверу Мемуарии.

## Что можно улучшать

Мы принимаем:

- исправления и уточнения русскоязычной документации;
- проверенные инструкции для MCP-клиентов;
- улучшения автоматической проверки подключения;
- безопасные примеры конфигурации без учётных данных;
- сообщения о проблемах совместимости и предложения новых сценариев.

Закрытый серверный код, инфраструктура, конфигурация развёртывания и данные пользователей разрабатываются отдельно и не должны добавляться в этот репозиторий.

## Сообщения об ошибках и предложения

Для технической проблемы или идеи выберите подходящий [шаблон GitHub Issue](https://github.com/memuaria/mcp/issues/new/choose). Для вопросов об аккаунте, книге или оплате напишите [Telegram-боту поддержки](https://t.me/memuaria_bot?start=help) или на [hello@memuaria.ru](mailto:hello@memuaria.ru).

Не публикуйте пароли, токены, файлы cookie, личные воспоминания, персональные данные и производственные журналы. Об уязвимостях сообщайте только по инструкции в [SECURITY.md](SECURITY.md).

## Локальная проверка

Требуется Node.js 20 или новее. В локальной копии репозитория выполните:

```bash
npm ci
npm run smoke
```

До запуска облачного сервера ответ `404` от `https://memuaria.ru/mcp` ожидаем. Для проверки другого окружения можно передать его адрес через `MEMUARIA_MCP_URL`.

Токен авторизации при необходимости передаётся только через переменную окружения `MEMUARIA_MCP_BEARER_TOKEN`. Никогда не добавляйте его в команду, файл, Issue, Pull Request или журнал.

## Как подготовить Pull Request

1. Создайте отдельную ветку от актуальной `main`.
2. Внесите одно связное изменение без постороннего форматирования файлов.
3. Используйте только вымышленные имена, истории, идентификаторы и адреса.
4. Проверьте команды, ссылки и названия пунктов интерфейса в актуальной версии клиента.
5. Выполните локальные проверки и убедитесь, что `git diff --check` не находит ошибок.
6. Кратко объясните в Pull Request, что изменилось и как это было проверено.

Для существенных изменений сначала создайте Issue, чтобы согласовать пользовательский сценарий и границы публичного репозитория.

## Язык и стиль

- Основной язык пользовательской документации — русский.
- Английский сохраняется для точных названий продуктов, команд, полей протокола и пунктов интерфейса.
- Пишите понятно и конкретно, без неподтверждённых обещаний о будущих возможностях.
- Добавляйте содержательные русские alt-тексты ко всем изображениям.
